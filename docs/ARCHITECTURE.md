# 技术方案

## 决策

- **界面**：.NET 10 LTS + WPF。原生 Windows 桌面技术，发布时可生成自包含应用。
- **存储**：SQLite，数据库位于用户本地应用数据目录。
- **访问方式**：轻量 SQL 仓储，不引入 ORM；当前数据模型很小，显式迁移更容易审计。
- **结构**：单应用项目，按 `Models`、`Data` 和窗口拆分。`works` 保存作品，`experiences` 保存每次阅读或观看，`progress_entries` 保存一次体验中的每日进度。

## 数据流

`作品窗口 / 经历窗口 / 进度窗口 → LibraryRepository → SQLite → 聚合查询 → 作品库 / 详情界面`

界面不直接拼接 SQL。数据库初始化和迁移集中在 `Database.cs`，读写与综合分查询集中在 `LibraryRepository.cs`。旧 `media_entries` 表只作为无损迁移和回退来源保留。

## 数据安全

- SQLite 启用 WAL 与外键约束。
- 写入使用参数化语句。
- 应用不会扫描用户其他目录，也不会发起网络请求。
- 导入功能实现前必须先定义冲突与回滚策略。

## 为什么暂不选其他方案

- WinUI 3 的部署面更复杂，本项目暂时不需要它独有的能力。
- Electron 会显著增加安装体积与运行开销。
- Tauri 体积小，但引入 Rust 与 Web 前端双栈，对这个单平台小工具没有明显收益。
